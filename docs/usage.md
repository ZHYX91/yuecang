# 使用与 AI 审阅

## 来源、图书与版本

来源是某次提取的文件内容，重复原件按 SHA-256 复用；不同文件名的导入仍可记录。图书表示作品身份，版本区分修订、译者或语言。混合文件不会被迫归入单本书：可以选择各内容块，普通文字还可选择 Unicode 码点区间。

先检查提取提醒，再归属或组稿。来源候选由文本指纹提供，候选相似不能证明是同一版本；搜索超过候选上限会显示未穷尽提示。不要把同名章节直接当成相同正文。明确忽略、重复或附属的来源区间可记录处置，原件仍保留。

结构块当前按整体选取。修改表格、公式等结构块的文字会将旧结构标为过时，导出使用修改后的文字并报告结构降级；可回看原资源，尚无完整所见即所得结构编辑器。

## 编码与乱码恢复

导入选项可指定 TXT/Markdown 编码。自动读取先处理 BOM，再检查无 BOM 的 UTF-16/32 字节分布，然后尝试 UTF-8 和 GB18030/Big5。无 BOM 的 Unicode 候选和 GB18030/Big5 多解会显示歧义。自动识别不能保证正确，请对照候选预览。

在来源中展开“重新解码与乱码修复”，选择编码和修复方式，预览前后结果后确认生成新来源。当前支持 UTF-8 被误读为 GB18030、Latin-1 或 Windows-1252 的严格往返恢复，以及显式 NFC 规范化、移除零宽空格和正文 BOM。只处理可逆的非 ASCII 字符段；混杂或已经丢失的字符不强行猜测，替换字符 `�` 会提示对照其他来源。NFC 和不可见字符清理也需要确认，可能有意使用的其他格式字符保留。

恢复最多处理 16 MiB 原件。原文件、原来源和已有归属不变；新来源记录原件、父来源和处理选项。需要把新来源重新归书、选入整理稿，不会自动替换已完成的工作。更换选项后必须重新预览。

## DOC 导入

先安装可选转换器。默认 `auto` 仅选择 LibreOffice；Windows 可以在导入选项明确选择 Word 或 WPS。也可在启动应用前设置环境变量 `YUECANG_LIBREOFFICE` 指向本机 LibreOffice 可执行文件。产品不下载 Office、不调用其他产品的私有环境。没有可用组件会保留原件并提示；安装后重新导入可再次提取。

转换使用任务内工作副本、独立 LibreOffice 配置或已证明归属的 COM 实例，禁用宏，再由现有 DOCX 解析器提取。转换后的 DOCX 也作为来源资源保留。转换默认最多 120 秒；失败不会静默换工具继续。Word/WPS 若不支持宏安全属性、实例归属无法核实，或无法绑定任务生命周期，将拒绝打开文件。若 COM 激活本身挂起而尚未返回实例身份，不能保证清理由系统激活的 Office 服务器；不会按进程名结束用户的 Office。不同 Office 版本的兼容性需要实际验证，注册检测不代表转换已通过。

## 疑似混书提醒与同版对齐

打开来源时会自动执行一次有预算的本地检查：书名标记、编号重置、相邻内容分别匹配已有明确归属的不同图书，都可能产生提醒。线索展示位置、前后文字与证据；可记为已核查、忽略或恢复待核查。新增归属后可点“检查来源线索”刷新。

文风或主题改变不能证明换书。续补、附录、引文、合刊和不同版本仍需分别判断；没有线索也不证明文件是单书。已知内容匹配只引用明确归属的原文区间，不通过相似候选传递作品身份。共享引文可以匹配多本书，保留这种歧义。达到来源、字符或计算预算时会显示分析未完成。

每次可选择 1–20 个线索生成离线 AI 核查请求，下载 JSON 后交给模型，回来选取对应历史请求并导入响应。请求冻结局部原文和匹配证据，响应限定为“可能混书 / 可能同一作品 / 依据不足”及理由；模型结果只保存为意见，不修改正文、归属或用户核查状态。此功能当前采用离线 JSON；正文校订的 HTTP 服务配置不会自动发送混书线索。

整理台“同版本内容对齐”只处理双方已归属到所选图书和版本的范围。精确重复、单侧独有、锚点间的不同文字以及无法确定对应的范围会分别展示，选取一侧后进入整理片段篮子，调整顺序再组稿。重复出现的段落会标为歧义，选材不自动去重、补章或跨版本融合。较长的结构块或缺少锚点的内容可能无法可靠配对。

同一内容块的重叠归属按已覆盖范围合并比较，不补入未归属的间隙。文字相同但结构或资源不同的块仍需核对。对齐界面显示将要选入的完整范围与资源；更新归属后需重新对齐，避免继续采用旧结果。

## 整理稿

来源选取的顺序就是整理稿顺序。跨版本选材时，明确勾选“确认为综合整理版，保留各版本出处”；该选择会冻结进修订元数据，原版归属与警告保留。未确认的版本混用会阻止定版。保存编辑创建新修订，不覆盖旧内容。正文、书名、作者、版本和来源一同冻结。两个窗口同时修改同一分支时，只有基于当前修订的提交成功，另一窗口需要刷新比较。

历史修订可以重新选作分支头；该动作不删除后来的修订。高级整理区支持从当前稿创建分支、修改冻结元数据和合并具有共同祖先的两条分支。非重叠文字修改自动组合；冲突先展示祖先、当前分支和另一分支内容，由用户选择一侧或填写自定义结果。结构重排、超预算差异或元数据分歧保留为未决，不自动猜测。定版表示用户选择了可输出修订，不证明源文件齐全。草稿亦可显式导出，导出清单保留其状态。

## AI 校订

离线审阅不需要密钥：生成审阅请求，保存或复制 JSON，交给模型处理，再在校订页导入响应。在线模式填写兼容 Chat Completions 的完整 HTTP 端点、模型名和 API 密钥；普通远程服务应使用 HTTPS。

长书按单次预算自动拆成独立请求，超长内容块按 Unicode 原坐标分片。校订页显示总片数、当前片范围和状态；需逐片完成，下载第一片不等于完成全书审阅。HTTP 模式逐片入队；整书总用量是各次请求的累加。

请求只含当前图书、当前版本已归属的局部来源区间及冻结整理稿；相近证据按有界词片段检索，不整库上传。书中指令只是待处理资料。响应格式、原文、范围、来源证据和重叠修改会被验证；数字、公式、表格等修改显示较高风险。提案必须接受才生效，也可以拒绝。

基于同一冻结修订、同一分支的非重叠分片校订可依次接受，应用会校验并调整位置。手工修改后旧提案不能直接应用，需要重新审阅。预算采用保守输入估计并限制输出长度；它是单次请求上限，不是服务商账单。

模型请求中断时可能已经计费，所以不会自动重发。先到服务商核实，再导入已有响应；确需重发时，在任务页选择“核实后重新请求”，并确认可能再次计费的提示。取消提示不会发送请求；已经保存的响应不会重复请求。普通失败任务可以重试，也可取消不再需要的任务。模型是否准确，需要结合原件人工确认；有证据链接不代表建议一定正确。

## 导出

Markdown、TXT 和 EPUB 都生成新的独立目录，含内容文件、资源、冻结修订与 manifest。不会覆盖已有输出。TXT 会明确报告不能表达的结构；原资源和来源信息随导出保留。可从导出页下载主文件，完整资源包在书库 exports 中。
